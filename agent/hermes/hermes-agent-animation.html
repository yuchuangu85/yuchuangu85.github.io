S2

一次 turn 的生命周期

13 个阶段，合并为 7 个可观察步骤

01build_turn_context恢复 prompt · 首轮压缩 · 租约
02assemble_api_request消息 + 工具 schema → 请求体
03perform_api_call可中断 HTTP · 流式
04check / normalize空响应 · 截断 · 统一形状
05run_tool_round执行工具 → 追加结果↺ 回到 02
06finish_text_response四道 stop gates 可能拒绝收尾
07finalize_turn落盘 · 刷记忆 · 触发复盘
回边模型返回 tool_calls 就回到 02，而不是重新开始 turn；预算 500 次，耗尽后还有一次"恩典调用"体面收尾。
S3

Prompt 装配

三层冻结，会话期间字节不变

SYSTEM PROMPT · 三层

stable身份 SOUL.md · 工具准则 · 编码守则 · 平台提示
context项目上下文 · worktree 快照 · 运维指令
volatile技能索引 · MEMORY.md · USER.md · 时间 · 运行环境

拼装结果

stable → context → volatile🔒 字节稳定
同一会话内不再重建；改写历史是唯一禁止的动作
缓存前缀复用98%
只有压缩允许打断缓存，其余注入一律走 user / tool 通道
代价改了技能/设置默认下个会话才生效——换来长会话成本线性而非平方级。
S4

工具调度

不是"有多个就并发"，而是分段规划

模型一次性返回 3 个 tool_call
1 read_file A
2 read_file B
3 patch_file C
parallel读读可并发
read A
read B
⛔ 写冲突 → 屏障
sequential与写操作有路径重叠
patch C
结果按原序回填 1 ✓2 ✓3 ✓ 完成顺序可以不同，写入历史的顺序永远是 1 → 2 → 3
