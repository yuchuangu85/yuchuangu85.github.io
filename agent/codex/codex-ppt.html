02 · CORE PRINCIPLE

Agent Loop：输出即下一轮输入

用户输入Op::UserTurn
→
组装 Promptbuild_prompt()
→
流式采样Responses API
→
执行工具ToolRouter
→
回填历史FunctionCallOutput
↺
最终回答TurnComplete
loop {
  let prompt = build_prompt(history, tools);
  let r = run_sampling_request(prompt).await;
  // 工具调用 → 执行 → 输出写回 history
  if token_limit_reached { run_auto_compact(); }
  if !r.needs_follow_up { break; }
}

循环终止条件只有一个

只要模型本轮发出任何工具调用，结果就必须回传给模型，因此 needs_follow_up = true，继续采样。模型只输出文本消息时循环自然结束。

源码：core/src/session/turn.rs · run_turn()

04 · ENTITIES

Session · Task · Turn

实体含义关键约束
Codex核心引擎，后台线程或独立进程运行只通过 SQ / EQ 与 UI 通信
Session当前配置与状态：模型、cwd、策略、历史同一时刻最多一个 Task；重新配置会中止执行
Task响应一次用户输入的完整工作新输入或 Op::Interrupt 会终止它
Turn一次"采样 → 执行工具 → 回填"迭代上一轮输出是下一轮输入；无输出则结束
ModelResponses API 或兼容 ProviderSSE / WebSocket 流式返回 ResponseItem

来源：codex-rs/docs/protocol_v1.md。需要并行时，为每条工作线运行独立的 Thread 或子 Agent。

05 · PROMPT

Prompt 组装与前缀缓存

// 每次采样都是一次完整请求
instructions: <基础系统指令>
tools: [exec_command, apply_patch,
        update_plan, view_image, mcp__*]
input: [
  developer: <权限 / 沙箱说明>
  user:      <AGENTS.md 指令>
  user:      <environment_context>
  ...history (只追加)
  user:      "本次输入"
]

AGENTS.md 发现

从 cwd 向上找到项目根（默认 .git），再从根到 cwd 逐层收集 AGENTS.md 并拼接，越靠近 cwd 优先级越高；再合并 ~/.codex/AGENTS.md。

只追加，不改写

静态前缀在前、历史在后，最大化 prompt cache 命中。配置变化以追加消息表达。请求默认无状态，推理以 encrypted_content 回传，兼容 ZDR。

07 · TOOLS

工具系统

工具作用
exec_command / write_stdinunified_exec：基于 PTY 的命令执行，支持长驻进程与交互输入，输出头尾截断
apply_patch自定义 diff 语法（*** Begin Patch）增删改文件，Codex 的主要编辑方式

request_user_input / 多 Agent结构化提问；派生子 Agent 并互相通信

arg0 分发：同一个 codex 二进制，argv[0]=codex-linux-sandbox 时变身沙箱 helper，argv[1]=--codex-run-as-apply-patch 时变身补丁工具。

08 · SECURITY MODEL

审批策略 × 沙箱策略

AskForApproval：何时问人
untrusted除 execpolicy 允许的命令外都要审批
on-request默认；模型按需申请提权（on-failure 为别名）
granular按类别细粒度开关
never从不询问，失败直接返回模型
SandboxPolicy：系统允许做什么
read-only全盘只读，默认断网
workspace-writecwd 与 writable_roots 可写，.git/.codex 只读
danger-full-access无限制
external-sandbox已在容器内，全盘访问

再叠加 execpolicy（Starlark prefix_rule：allow / prompt / forbidden）与 network-proxy，形成纵深防御。

09 · OS SANDBOX

各平台沙箱实现

macOS

Seatbelt

/usr/bin/sandbox-exec 加载动态生成的 SBPL profile：按可写根放开 file-write*，拒绝网络，保留偏好设置读取。

Linux

bubblewrap + seccomp

--ro-bind / / 默认只读，--bind 叠加可写根，受保护子路径重新只读；PR_SET_NO_NEW_PRIVS + seccomp 屏蔽网络与 io_uring。Landlock 为旧路径。

Windows

Restricted Token

非提权模式用受限令牌；提权模式支持精确读写根与只读子目录。无法强制执行的策略 fail closed。

10 · TOOL ORCHESTRATOR

审批 → 沙箱 → 升级重试

execpolicy + 策略Skip / NeedsApproval / Forbidden
→
请求审批ExecApprovalRequest
→
沙箱内首次执行SandboxManager
→
沙箱拒绝?SandboxErr::Denied
→
再审批 + 无沙箱重试escalated

审批决策 ReviewDecision

Approved、ApprovedForSession（会话缓存）、ApprovedExecpolicyAmendment（写入规则）、Denied、Abort。也可由 Guardian 自动审查代为决定。

谁来决定升级

untrusted：沙箱失败后自动请求无沙箱重试。
on-request：不自动升级，拒绝信息返回模型，由模型带 require_escalated 显式申请审批。
never：从不询问，失败直接交给模型处理。

11 · CONTEXT & PERSISTENCE

上下文压缩与会话持久化

1触发：token 超过 model_auto_compact_token_limit 且仍需继续；采样前或切换小窗口模型时也会检查
2摘要：本地用压缩提示词总结；远程模式由 Responses API 返回不透明的 Compaction item
3替换：SUMMARY_PREFIX + 摘要 + 最近用户消息，重新插入初始上下文
4继续：同一 Turn 接着采样；也可 /compact 手动触发

12 · END-TO-END

一次请求的完整时序

1TUI 发送 Op::UserTurn
2Session 启动 RegularTask → TurnStarted
3组装 Prompt，流式请求 Responses API
4模型调用 exec_command: cargo test
5Orchestrator：Skip 审批，沙箱内执行
6失败输出回填，needs_follow_up=true
7模型发出 apply_patch，自动批准写入
8重新测试，需联网 → 沙箱拒绝
9模型 require_escalated → 用户批准
10无沙箱执行通过；超阈值自动压缩
11模型输出总结，无工具调用 → 退出循环
12TurnComplete，rollout 落盘

逐步动画演示见 codex-animation.html

14 · TAKEAWAYS

设计取舍

引擎与 UI 解耦

SQ/EQ 让 TUI、IDE、App、MCP Server 共享同一个 core。

单 Task 模型

每个 Session 一次只跑一个 Task，避免并发编辑冲突。

纵深防御

规则 + 审批 + OS 沙箱 + 网络代理；不能强制执行就 fail closed。

只追加 Prompt

最大化前缀缓存命中；无状态请求兼容 ZDR。

补丁式编辑

输出更短、更易审阅，UI 直接渲染 diff。

Rust 单二进制

启动快、无运行时依赖，沙箱 helper 与补丁工具内置。
