01 · WHAT IS CLAUDE

模型负责思考，Harness 负责行动

Model

Claude 模型

Fable 5.1 · Opus 5.5 · Sonnet 5.5 · Haiku 4.5，在能力、延迟、成本间取舍。

API

Messages API

无状态：输入 system + tools + messages，输出 text / thinking / tool_use 内容块。

Harness

Claude Code

终端 / IDE / 桌面 / Web 中的 Agent：执行工具、管控权限、管理上下文。

SDK

Agent SDK

把同一套 Agent 循环开放为 Python / TypeScript 库。

"The agentic loop is powered by two components: models that reason and tools that act. Claude Code is the layer around the model that provides the tools and manages the context the model sees."

04 · INTERPRETABILITY

AI 显微镜：Features → Circuits

多语言

共享概念空间

不同语言的同一含义在内部高度重叠，像一种通用"思维语言"。

规划

提前想好韵脚

写诗时先选定押韵词再组织句子：一次输出一个 token，但会看得更远。

忠实性

CoT 可能是编的

给出错误提示时，模型会构造迎合用户的推理，并被工具"当场抓到"。

幻觉

默认不猜

默认回路是拒答，"已知实体"特征抑制它才会回答；误抑制导致幻觉。

局限：即使几十个词的提示，也只捕捉到总计算量的一小部分，且需数小时人工分析。
— Tracing the thoughts of a large language model（研究对象 Claude 3.5 Haiku）

05 · REASONING

Extended Thinking 与 Effort：两个独立旋钮

// 请求
thinking: { type: "enabled",
            budget_tokens: 10000 }
// 响应
content: [
  { type: "thinking",
    thinking: "先分析失败用例…",
    signature: "EqQB…" },
  { type: "tool_use", name: "Bash", … }
]

thinking 块 + signature

多轮工具调用时原样回传 thinking 块，模型在 tool_result 之后接着原思路继续（interleaved thinking）。

effort: low → max

控制每次回复的推理深度与 token 投入；与 thinking 相互独立，可任意组合。

06 · TOOL USE

模型只"写出"调用，Harness 负责执行

1请求携带 tools[]：name + description + JSON Schema（描述质量决定调用质量，即 ACI 设计）
2模型输出 tool_use {id, name, input}，stop_reason = "tool_use"
3Harness 做权限检查 → 执行 → 把 tool_result {tool_use_id, content, is_error} 作为 user 消息回填
4再次调用模型；直到输出纯文本，stop_reason = "end_turn"

Client tools

调用方执行：Read / Edit / Bash 等。

Server tools

平台执行：web search、code execution。

并行调用

一次响应可含多个 tool_use，只读可并发。

07 · CONTEXT & CACHING

无状态 API 下的两件大事

Context Window
200K

标准上下文（部分模型/配置 1M）。system、工具、历史、工具输出全部计入；长任务必然逼近上限 → 需要压缩、隔离、按需加载。

Prompt Caching
tools → system → msgs

cache_control: ephemeral 标记前缀断点，默认 TTL 5 分钟（可选 1 小时），命中部分大幅折扣。Agent 每轮重发相同前缀，缓存是成本与延迟的关键。

设计含义：动态信息（system-reminder、文件变更提示）追加在消息尾部，不去改动 system prompt，以免整段缓存失效。

09 · AGENTIC LOOP

一个围绕 Messages API 的 while 循环

while (true) {
  if (nearLimit()) compact()   // PreCompact
  resp = claude.stream(system, tools, history)
  yield AssistantMessage(resp.blocks)
  calls = resp.tool_uses
  if (!calls.length) break   // end_turn
  results = runTools(calls)
    // 权限 → PreToolUse → 执行 → PostToolUse
  history.push(resp, results)
  if (turns ≥ maxTurns) return error
}
Stop hook → ResultMessage
消息含义
Systeminit · compact_boundary
Assistanttext / thinking / tool_use
Usertool_result · 插话
StreamEvent流式增量
Result结果 · usage · 成本 · session_id

人在回路：Esc 立即取消当前工具；直接输入回车 = 排队消息，工具结束后同一轮内被读取。

09 · EXAMPLE

"修复 auth 失败的测试" 的 turn 序列

Turn 1Bash npm test
→
Turn 2Agent(Explore)
→
Turn 3Read ×2 并行
→
Turn 4Edit token.ts
→
Turn 5Bash npm test ✓
→
Finaltext · end_turn
Gather

收集上下文

跑测试拿失败信息；派子代理调研，只收摘要。

Act

采取行动

精确字符串替换；编辑前快照；Hook 自动格式化；LSP 诊断。

Verify

验证结果

再次运行测试，命中已保存的 allow 规则直接执行，全部通过才收尾。

配套动画 claude-animation.html 逐步演示了这一过程中的数据流、权限决策与上下文变化。

11 · SAFETY

权限 · 沙箱 · 检查点

Permission modes

Shift+Tab 切换

auto 分类器审阅 · default 询问 · acceptEdits · plan 只规划 · dontAsk · bypassPermissions（仅隔离环境）

Rule evaluation

deny 优先

PreToolUse hook → deny → ask → allow → 模式兜底。任何层级的 deny 都无法被其他层放开；managed 最高。

Sandbox

OS 级隔离

macOS Seatbelt · Linux/WSL2 bubblewrap。写入限于工作目录，网络按域名白名单走代理。

Checkpoints

编辑可撤销

每个新 prompt 建检查点，编辑前快照，保留最近 100 个；Esc Esc / /rewind 回退。

Boundary

覆盖不到的

Bash 造成的改动、子代理编辑、远程副作用（DB / 部署）—— 交给权限控制。

12 · CONTEXT ENGINEERING

保护"注意力预算"

JIT

按需检索

只留路径引用，用 Grep / Read 即时拉取。

Lazy

延迟加载

Skill 只放描述、MCP 只放工具名。

Isolate

子代理隔离

读几十个文件，只回传摘要。

Compact

自动压缩

先清旧工具输出，再摘要历史。

压缩后内容
从磁盘重新注入项目根 CLAUDE.md、无路径规则、Auto memory、plan 文件、skill 描述
重新读取最近修改的至多 5 个文件（>5k tokens 只留路径）；已调用 skill 正文（单个 5k / 总计 25k）
可能丢失早期对话中的细节指令 → 持久规则写进 CLAUDE.md
13 · MEMORY

跨会话记忆只靠落盘文件

→
./CLAUDE.md团队共享
→
CLAUDE.local.md个人本项目
+
MEMORY.mdAuto memory

拼接，不覆盖

从文件系统根到当前目录依次拼接，越近越后读；子目录 CLAUDE.md 按需加载。

体积约束

CLAUDE.md ≤ 4 MiB 全量加载（越短越好）；MEMORY.md 只加载前 200 行 / 25KB，主题文件按需 Read。

组织方式

@path 导入；.claude/rules/ 用 paths: 限定范围；HTML 注释注入前剥离。

14 · EXTENSIONS

Skills · MCP · Hooks · Subagents

Skills

可复用的指令包

SKILL.md + 资源。开局只见描述，调用时加载正文（渐进式披露）；可 context: fork、allowed-tools。

MCP

开放的外部连接协议

stdio / HTTP / SSE / WebSocket；local / project / user 作用域；OAuth；工具名 mcp__server__tool。

Hooks

确定性的生命周期钩子

SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · Stop · PreCompact …；command / http / mcp_tool / prompt / agent 五种处理器；exit 2 阻断。

Subagents

隔离的工作者

独立上下文与 system prompt，限定工具/模型，可 worktree 隔离、可后台；内置 Explore、Plan；Fork 继承父对话。

上下文成本：CLAUDE.md 每次请求 · Skills 低 · MCP 用前很低 · Subagents 隔离 · Hooks 为零（除非返回附加上下文）

16 · DESIGN

设计取舍

选择理由
单循环 + 强工具"从最简单的方案开始，只在需要时增加复杂度"（Building effective agents）
模型自主决定下一步编码子任务不可预知；靠环境反馈（测试、报错）判断进展
Agentic search 代替索引始终看到最新代码，无需维护向量库
deny 优先 + 沙箱组织策略不可覆盖；"要不要做"与"能碰到什么"双保险
规则写文件、扩展按需加载压缩会丢细节；工具越多越难选对，保护注意力预算
SUMMARY

Claude = 会思考的模型
Claude Code = 让它可靠做事的 Harness

1模型：预训练 + SFT + RLHF / Constitutional AI，并以可解释性研究持续理解其内部机制
2协议：tool_use / tool_result + thinking + prompt caching，是一切 Agent 能力的接口
3Harness：gather → act → verify 的循环，加权限、沙箱、检查点、上下文工程与扩展层
